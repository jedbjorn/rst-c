# Ribbon Tool Census

Which Revit ribbon tools actually run, where. One table per Revit year, produced by starting every stock ribbon
tool in a fixed set of contexts on a test machine.

Revit's own live checks answer most questions about a ribbon tool at run time: whether its tab and panel are
showing, and whether Revit greys it out (`CanExecute`). Two things they cannot see:

- **Tools Revit calls clickable that do nothing** in this kind of file and view. The journal usually says
  `cannot be invoked in this context`.
- **Tools Revit models but never draws** at a ribbon place. The ribbon model reports them visible and enabled,
  but no button is drawn there.

This census finds both by running every tool. RST (the add-in in this repository) ships the short list of
exceptions with each install. The full table is published here so other add-in developers don't have to
measure it again. MIT, like the rest of the repository.

## Files

| File | What it holds |
|---|---|
| `<year>/full.tsv` | Every ribbon place of every command id in every context, with its result. The published table |
| `<year>/exceptions.tsv` | Only the `not-runnable` and `not-drawn` places. RST embeds this file as it is (no second copy) |
| `<year>/contexts.tsv` | Each context key, the file kind, family category and placement type, the view, and the stock template(s) |
| `diff-2027-vs-2026.md` | Ids added and removed, and results that changed, per context (generated by `tools/census/diff.py`) |

All files are UTF-8, tab-separated, with a header row. They hold command ids, English ribbon labels, ribbon
places and results. They hold no icons and no screenshots.

### `full.tsv` columns

| Column | Meaning |
|---|---|
| `year` | Revit year |
| `build` | The running Revit's version and build, as Revit reports it (`SubVersionNumber (VersionBuild)`) |
| `context` | The context key (below) |
| `id` | The command id (`RevitCommandId.Name`): `ID_OBJECTS_WALL`, or `CustomCtrl_…` for an add-in button |
| `tab` | The ribbon tab's id (language-independent: `Architecture`, `Home_Family`) |
| `panel` | The panel's title (English) |
| `path` | The containers between the panel and the item: `/SlideOut` when it sits in the panel's slide-out, then `/<Type>(<id or text>)` per container (split button, stack, fold panel, menu); `DialogLauncher` for a panel's launcher arrow; empty when the item is straight on the panel |
| `label` | The English ribbon text |
| `result` | See [Results](#results) |
| `tested` | How the id was tested: `gate` (only `CanExecute` was asked), `bind+cancel`, or `real` (really started, then torn down); empty when nothing was asked |
| `opened` | What a real start opened: `revit-dialog`, `win32`, `wpf`, `webview2`, `external-process:<exe>`, `browser`, `placement`, `sketch`, `pick`, `doc-change`, `pane`; several are comma-separated |
| `teardown` | What the teardown did (`none` when nothing was left). A `skipped` row carries `skip: <reason>` here instead |
| `left` | Anything still open after the teardown; empty when the idle proof passed |
| `gate` | The `CanExecute` answer at test time: `True`, `False`, `False(own)` (the add-in's own handler), `False(IsEnabled)` |
| `ms` | Time spent on the id |
| `run_date` | Date of the run |
| `census_build` | The census add-in build (version, commit and a hash of the DLL) |

The result belongs to the id in that context; a place gets `not-drawn` instead when that place is not drawn.
Where an id has several places, it was started once, from a drawn place. Revit keeps hidden copies of some
containers (a second Paint or Dimension split button, the other size of a fold panel); copies with the same tab,
panel and path are one row, drawn if any copy is drawn. A copy with its own path (`Dimension_Split_Button_1`) keeps
its own row, so a `not-drawn` row applies to its exact path only.

### `exceptions.tsv` columns

`context`, `id`, `tab`, `panel`, `path` (as in `full.tsv`), `mark` (`not-runnable` or `not-drawn`) and `reason`
(short: the journal line, or how the place was found not drawn).

### `contexts.tsv` columns

`context`, `kind` (`project` or `family`), `category` and `placement` (families), `view_type`, `view` (the view the run
used) and `templates` (the stock template opened, then every stock template that gives the same category and
placement type).

## Contexts

A context is what the index is keyed on, in terms an add-in can read at run time from the active document and view:

| File kind | Key | Contexts run |
|---|---|---|
| Project (`.rvt`, from `English-Imperial/default.rte`) | `project/<ViewType>` | `FloorPlan`, `CeilingPlan`, `ThreeD`, `Section`, `Elevation`, `DrawingSheet`, `DraftingView`, `Legend`, `Schedule` |
| Family (`.rfa`, from the stock English templates) | `family/<BuiltInCategory>/<FamilyPlacementType>/<ViewType>` | One per distinct category and placement type among the stock English and English-Imperial family templates, in the view the family opens in and, where the template has one, a 3D view |

The parts are Revit enum names (`Autodesk.Revit.DB.ViewType`, `BuiltInCategory`, `FamilyPlacementType`), for example
`project/FloorPlan` or `family/OST_GenericModel/OneLevelBased/FloorPlan`. A project template (`.rte`) uses the project
rows. A key with no rows (a family kind not run, a newer view type) means the census has nothing to say there.

Every context runs with nothing selected, in a new scratch document that is never saved.

## Results

| Result | Meaning | In `exceptions.tsv`? |
|---|---|---|
| `executes` | It started: the command event fired, or a real start opened a window, mode, dialog or change | no |
| `greyed` | `CanExecute` is false, so Revit greys it; a live check sees this | no |
| `accepted-nothing` | Clickable, accepted, and nothing started | yes, `not-runnable` |
| `not-drawn` | Modelled at this ribbon place but not drawn there | yes, `not-drawn` |
| `refused` | `PostCommand` throws and the ribbon's own command path is not possible | yes, `not-runnable` |
| `skipped` | On the skip list (it crashes Revit, or it sends data out); never started | no |
| `not-a-command` | A container (split button, combo, gallery) or an id Revit does not resolve | no |

`error` (an exception, a crash, a hang) is never committed: each one is re-run, skipped with a reason, or reclassified
before a table is committed.

A place that is not drawn and whose id also does not run is recorded as `accepted-nothing` (shipped as
`not-runnable`); its reason says the place is not drawn either.

## Method

The census is a Revit add-in (`src/RST.Census`, never shipped) driven by a host script (`tools/census`) on a Windows
test VM. For each context it:

1. **Walks the ribbon**: every item with a command id on the visible, non-contextual tabs (in a family, never a hidden
   tab: asking `CanExecute` there can crash Revit).
2. **Skips third-party buttons.** Only stock Revit is classified: Revit and the add-ins Autodesk ships with it. A button
   whose add-in has a non-Autodesk vendor id (from its `.addin` manifest), and a native id such an add-in has bound, get
   no row. The run summary counts them.
3. **Checks what is drawn.** For each tab it activates the tab, opens every dropdown, slide-out and collapsed panel, and
   reads WPF's visual tree for a visible control bound to each ribbon item. A place on a visible panel that is never
   seen drawn is `not-drawn`. A place on a panel Revit hides in that context keeps its id's result: an add-in sees a
   hidden panel itself (`RibbonPanel.IsVisible`), so the census adds nothing there.
4. **Asks the gate**: `CanExecute` (Revit's global ribbon handler `Autodesk.Windows.ComponentManager.CommandHandler`;
   for an add-in button its own handler; and `IsEnabled`). False: `greyed`.
5. **Starts the tool.** If the id accepts an `AddInCommandBinding`, the census binds it with only a `BeforeExecuted`
   handler that sets `Cancel`, then posts it (`UIApplication.PostCommand`, or the ribbon's own command path
   `ComponentManager.CommandHandler.Execute(item)` for ids Revit won't let add-ins post). The event firing means it
   starts; nothing happens because it is cancelled. Ids that can't be bound (add-in commands, native ids another stock
   add-in binds) are started for real.
6. **Tears down** what a real start opened: Revit dialogs (answered Cancel through `DialogBoxShowing`), Win32 and WPF
   windows, windows of other processes it started (including browsers and WebView2), placement, sketch and pick modes,
   committed transactions (undone), and dockable panes.
7. **Proves Revit idle** before the next tool: no extra window, no active mode, an `ExternalEvent` round trip completes.
   Anything left is recorded in `left`.

Each scratch document ends with its starting element count; the run summary records it per context.

## Limits

- **Stock Revit only.** Third-party add-ins have no rows. Their buttons are listed live by RST and are runnable unless
  Revit greys them.
- **English Revit.** Rows are keyed by command id, so they apply in any language; only `label` and `panel` are English.
  `tab` is the tab's id.
- **Contexts are a fixed set**: nothing selected, no contextual tabs (`Modify | Walls`), no File menu, Quick Access
  Toolbar, view control bar, right-click menus or shortcut-only commands. Tools that start and then wait for a pick
  (Move, Copy, Align) count as `executes`.
- **One machine, one build per year**, at one screen size (a fold panel draws different items at other widths: Stair by
  Sketch is the known case). A different update of the same year may differ; the census is re-run when RST moves to
  a new build.
- **Real starts are what a user gets with the stock add-ins loaded.** An id another add-in intercepts is classified as
  stock Revit behaves.
- **Undocumented API.** `ComponentManager.CommandHandler` is a public member of AdWindows, which is not part of the
  documented Revit API. It is re-checked every year by this run.
- `skipped` rows say nothing about the tool.

## Third-party add-ins and corrections

The census covers stock Revit only. If you maintain an add-in, or you found a row that is wrong on your machine:

- **Open an issue** on this repository with the Revit year and build, the command id, the ribbon place, the file kind
  and view, and what happens when you click it (the journal line helps).
- **Or open a pull request** changing the row, with the same information. A change is reproduced on the test VM before
  it is merged, and reaches RST users with the next release.

There is no SDK for adding your own ids to RST's index.

## Running the census

The release procedure, on a new Revit year or a build bump before a release, for every year RST ships:

1. **Run it on the VM** (`tools/census/census.py`; the test-seat rules in the Planner's `rst_c_vm` skill apply):

   ```bash
   cd tools/census
   ./census.py status                 # the shared VM must be powered off and free
   ./census.py build                  # RST.Census for 2026 and 2027 (.NET 10 SDK for 2027)
   ./census.py begin                  # start the VM and the MCP relay, probe the guest
   ./census.py prepare 2026           # stage the add-in and skip list, park RST's own manifest
   ./census.py start 2026             # Revit on the console desktop; answers Always Load
   ./census.py survey 2026            # stock family templates -> categories and placement types
   ./census.py plan 2026              # the context plan
   ./census.py all 2026 --until 05:30 # every context, unattended, with the watchdog; resumable
   ./census.py pull 2026              # evidence to shared/evidence/census/2026/ (internal, never committed)
   ./census.py end                    # MCP down, pull, reset the VM to off
   ```

   A year can span several VM sessions: the next session's `prepare` pushes the pulled rows back and `all` resumes
   after the last finished tool. The watchdog restarts Revit after a crash or a hang, puts that tool on the skip list
   with its journal line, and continues.
2. **Resolve every `error` row and review new skip-list entries** (`tools/census/skip.tsv`: year, id, reason).
3. **Assemble and diff**: `./assemble.py 2026`, `./assemble.py 2027`, `./diff.py 2026 2027`. Commit `full.tsv`,
   `exceptions.tsv`, `contexts.tsv` and the diff in one pull request; the reviewer reads the diff. `RST.Tests`
   (`CensusFilesTests`) checks the tables' rules.
4. **Reports** from users (issues, pull requests) are reproduced on the VM before they change a row, and reach users
   only with a release.

Screenshots, journals and run logs are internal evidence and are never committed here.
